# Data

Server state is a cache of data owned elsewhere, managed by a server-state library, never copied into component or global client state. Data a page needs is fetched by its route, not discovered by its components, so loading starts on navigation or link preload instead of after render and requests never waterfall.

Each resource has one module of query factories that co-locates keys and fetchers: a hierarchy of keys (`all`, `lists`, `list(filters)`, `details`, `detail(id)`) and an options factory per read built from them. The route's loader prefetches through the factory and the component reads the same factory with the suspending hook, so the component renders with data present and never branches on loading, and the key is written once. Reads that depend on an optional value use the library's skip token or a disabled option, never a conditional hook call. Derive and select inside the query's `select` when a view needs a slice or a sorted, grouped or filtered form of the data, so the transformation is memoised with the cache and shared by every reader.

Writes are one hook per operation wrapping the mutation, invalidating through the key hierarchy and returning that promise from the settled callback so the mutation stays pending until fresh data has arrived and the screen never shows stale data. Invalidate the narrowest slice that changed and the lists that contain it; a broad refresh is one call on `all`. When a write is cheap and likely to succeed, show it optimistically: render the pending variables in place for a single screen, and only patch the cache with snapshot and rollback when several screens must agree before the server answers. Destructive writes either confirm first or offer undo; prefer undo, it costs the user less.

Services export one plain object of typed async endpoint methods per resource and are the only code that knows the transport: base URL, headers, serialisation, errors. Views, components and hooks above the query layer never import them. Responses are parsed at this boundary against a schema, so a changed API fails loudly at the service instead of as `undefined` deep in a component. Errors carry a status and a user-facing message; the service maps transport failures into them.

A reactive backend keeps the same shape: its generated, typed queries and mutations stand in for the service and fetcher, the per-resource module still names what the feature reads and writes, and views still never call the transport directly. Subscriptions replace manual invalidation there; do not layer polling or refetching on top of a live query.

Domain types live with the resource's API code as `type` aliases, preferably inferred from the same schemas the service parses with, so the runtime check and the static type cannot drift. Models are factory functions that fill defaults for every shape a form creates, nested ones included, so no form builds an empty record from an inline literal. Fixtures and mock services implement the same service interface as the real one, with realistic latency, so swapping them is a one-line change.
