# Routing

The router owns navigation, data loading and URL state, so a page is defined by its route: what it needs before it renders, what the URL can say about it, and what to show while waiting or on failure. Use the framework's file-based routes and its generated, typed route tree; never hand-register routes or reach for string paths without types.

Route files stay thin: they declare the route (path params, search schema, loader, pending, error and not-found components) and point at a view from the feature folder. Layout routes render the shared shell and an outlet for their children; a route that has child routes must render an outlet, or its children never appear. Nesting follows the URL and the screen at the same time: a detail panel that slides over a list is a child of the list route, an edit screen that replaces the detail is a sibling of it. Group folders that do not add to the URL only organise files and cannot hold layout; use a pathless layout route for a shared shell instead.

Loaders start data fetching on navigation and, with intent preloading on, on hover, so the page renders with its data instead of fetching after mount. A loader ensures the data its view reads through the data layer's cache rather than returning ad hoc values the view reads separately, and it declares exactly which search params it depends on so it reruns only when they change. Anything the loader needs, such as the query client or the current user, arrives through router context, never imported as a global.

Params and search params are typed and validated at the route: path params are read through the route's own hooks, never cast, and search params go through a schema with defaults so a hand-edited or stale URL degrades to a valid state instead of crashing. Search params are the home for state a user would share or expect back after a reload or the back button: search text, filters, sort, page, the open tab, the selected item when it is not its own route. Update them through typed navigation that merges into the previous value, and debounce or replace history for keystroke-driven changes so the back button is not flooded.

Every route that loads data declares a pending component that mirrors the page's final layout and an error component that explains the failure and offers a retry, and every route with an id declares a not-found component reached by throwing the router's not-found from the loader. Auth and other guards run before load in the route's guard hook and redirect with the intended destination preserved; components never check auth and redirect themselves.

Navigation uses the router's typed link and navigate APIs. Links are links: anything that changes the URL is an anchor, so open-in-new-tab, middle-click and the browser's own affordances keep working, and a button wrapping a link must render as the link, not as a button holding one.
