name: clipping-streamer-shorts
description: Use when cutting a ranked streamer-moments Short from a YouTube video with yt-dlp and Diffusion Studio.
---

A Short is a Top 3 countdown of moments from one source video: the audience picks the moments through YouTube's most-replayed heatmap, only the bytes around them are downloaded, and a Diffusion Studio project built from the bundled template crops each moment to 9:16, captions it word by word, and bleeps its swears. The pipeline runs in order, research, moments, download, project, framing, captions and bleeps, verification, export, and every stage has a bundled script or template in this folder (`scripts/`, `template/`) so the agent fills in parameters rather than rewriting the plumbing. Free paths come first everywhere, YouTube's heatmap and auto-captions instead of Diffusion's paid `media listen` and `media transcribe`, since credits cost real money and the free plan is a one-time 50.

Before any download, state its size in MB or GB and choose the smallest viable option, never a full video (a 54-minute 4K stream is about 5 GB), this is a hard preference, not a courtesy. Channel format decisions live in the channel's own docs (for TheShortlist, `C:\Users\DavidOdunjo\Codebase\YouTube\TheShortlistOfficial\docs\decisions.md`), read them first and let them win over the house style below when they disagree.

**Finding moments**

Search with `yt-dlp --flat-playlist "ytsearch10:<streamer> <topic>"` and confirm the uploader from each result's `channel_url`, since guessed handles are often someone else (`@marlon` is not Marlon). Keep yt-dlp current with `yt-dlp -U`, winget's upgrade fails on the portable package. Pipe `yt-dlp -j --skip-download <url>` into `bun scripts/peaks.ts` for the top most-replayed peaks, a video only days old may have no heatmap yet, so pick an older one or wait. Then fetch the free word-level captions with `yt-dlp --skip-download --write-auto-subs --sub-langs en --sub-format json3 -o "<project>/_session/%(id)s" <url>` and read about a minute either side of each peak to learn what actually happens there. Rank by heatmap value, highest is #1, so the order is audience-ranked rather than the agent's taste. A moment must stand alone with no prior context, open on its hook, and end on a clean line, never on a swear sitting on the cut; the whole Short lands around 45 to 55 seconds.

**Downloading**

`yt-dlp --download-sections` does not work for this, YouTube's fragmented MP4 cannot be seeked so ffmpeg reads from the start, ffmpeg's HTTP seeks on VP9 hang, and `--force-keyframes-at-cuts` re-encodes 4K on the CPU. Use `python scripts/clip.py <url> <project> <name>=<start>-<end> ... --estimate` to print the size (it only fetches the two stream headers, about 2 MB), report it, then rerun without `--estimate`. It reads each WebM stream's Cues index, fetches only the clusters covering each range padded by 8 seconds, and writes `assets/a-roll/<name>.mp4`, VP9 1080p (format 303) and Opus (251) by default; three moments of about 2.5 minutes is roughly 50 MB. It aligns audio to video itself, because the spliced audio starts up to 8 seconds before the video and ffmpeg rebases each input to zero separately, and it fails loudly if the muxed streams don't both start at zero. Each clip prints its `src`, `fileZero` (the source time of its first frame) and the unpadded `sourceIn`/`sourceOut` in the file's own time, paste those into `segments.ts` with a rank. Stream URLs expire after a few hours, rerun if a fetch starts failing.

**Building the project**

Each Short is its own folder, named by its number then its slug (for TheShortlist, `C:\Users\DavidOdunjo\Codebase\YouTube\TheShortlistOfficial\shorts\<NNN>-<slug>\`, e.g. `001-marlon-vs-speed-10k-fifa-wager-top-3`). Only the folder carries the number. Copy `template/index.tsx`, `template/segments.ts` and `template/bleeps.ts` into it, then `diffusion open <abs dir>` in the foreground, never `-b`, so David watches the edit take shape in the app; it keeps the files and adds the project record to `package.json`. `segments.ts` is the single source of truth for rank, clip, `fileZero` and trim, in countdown order #3, #2, #1, and everything else derives from it. The app rewrites `index.tsx` after every compile to stamp ids, so re-read it before each edit. The scene carries `id="short"`, so `check short`, `capture short` and `export short` address it without looking the id up. Name the scene, the export file and `upload.json`'s `video` path after the content, one lower-kebab-case slug for all three, never a generic name like `short-001` (`marlon-vs-speed-10k-fifa-wager-top-3`).

**Framing**

Look before cropping: `diffusion media grab a-roll/<name>.mp4 -c 12 -s <in> -e <out>` gives a contact sheet per moment, read it and set that rank's `SHOTS` entry in source pixels. Match the layout to what the stream shows: gameplay with a facecam uses `split(gameplay, facecam)`, gameplay 1080×520 over facecam 1080×600, an IRL camera uses `single()` on a wide region (about 1300×1080) so two people at opposite edges both stay in, and a screen recording with a facecam uses `single()` on the facecam alone, since screen text is unreadable on a phone. Every crop is a `<rect mask>` inside its video, and it needs explicit `start={0} end={sourceOut}`, without them the mask stops clipping partway and the rest of the source frame leaks in. Only the first shot of a split is audible, the rest are `muted`, so audio never doubles.

**House style**

The approved look, Short #001 (`C:\Users\DavidOdunjo\Codebase\YouTube\TheShortlistOfficial\shorts\001-marlon-vs-speed-10k-fifa-wager-top-3\exports\marlon-vs-speed-10k-fifa-wager-top-3.mp4`), is what the template renders, change only its `@inspect` values per Short. A black 1080×1920 scene, the title in Inter 800 at 46 px white centered at y 120 (`STREAMER vs STREAMER · HOOK`, uppercase), the rank `#N` in Inter 900 at 200 px in the accent `#A47CFF` (the channel logo's purple) at y 190 to 410 with a 0.35 s `grow`, content from y 440 to 1560, `classic` captions one word at a time centered with `offsetY` 720, and a 0.3 s `fadeToWhite` between moments. Source audio only, no music, TikTok sounds aren't licensed for YouTube, and the YouTube Audio Library is the safe source if music is ever wanted.

**Captions and bleeps**

Swears are masked in captions and bleeped in audio, since YouTube limits ads on profane Shorts. Run `bun scripts/captions.ts <project> <project>/_session/<id>.en.json3`, which writes `assets/captions.srt` (one word per cue, `>>` speaker marks stripped, `f**k` style masks), `bleeps.ts`, and `assets/sfx/bleep-track.wav`, a single timeline-long track with a 1 kHz tone only inside bleep windows. Rerun it after every change to `segments.ts`, timeline times shift whenever any moment's length does. The template mutes the audible shot with `steps(1)` volume keyframes to -60 dB inside each window and plays the one bleep track from 0. It is one track rather than an `<audio>` per bleep because the app stamps one id per JSX element, not per loop instance, so audios inside a `<For>` share an id and only the first plays, and a computed `id={...}` gets re-stamped. A new or renamed asset can resolve as failed until its filename changes, if the bleep track shows as failed, rename the file and its `src`.

**Transitions**

`transition` only works on direct children of `<sequence>`, so each moment is a `<group>` there, and every group but the last carries it. Use `fadeToWhite`, the slides move the clip without its mask and leak the uncropped source across the frame.

**Verifying and exporting**

Run `diffusion check short` until it reports no issues, then `diffusion capture short -t ...` across each moment and at 0.1 s either side of each cut to see the flash and confirm nothing leaks, and read the sheets. Export only when David asks, with `diffusion export short <abs project>\exports\<slug>.mp4`, the defaults give 1080×1920 H.264 at about 12 Mbps. Then prove the bleeps landed in the rendered file with `bun scripts/verify-bleeps.ts <project> <export>`, which checks each window for the tone against the half second before it and for muted speech against the Short's average, and fails if either is missing.

The Short ends by handing off to its `upload.json`, which sits in the project folder and points `video` at the export, the uploader reads it and uploading is not part of this skill. Its fields and rules live in the channel's upload doc (for TheShortlist, `C:\Users\DavidOdunjo\Codebase\YouTube\TheShortlistOfficial\docs\uploading.md`), follow them there and take Short #001's `upload.json` as the reference.

**Housekeeping**

Name the folder right when you create it, because renaming later is painful: Diffusion Studio locks an open project's folder, and even after it quits something (Explorer, VS Code) can keep holding the folder itself, while every file inside stays movable. If a rename is denied, create the new folder, move the contents across (hidden files included), remove the empty old one, update `name` and `displayName` in the project's `package.json`, then `diffusion open <new dir>` and `check short` to confirm it loads. The project id survives the move. After a Short is published, log it in the channel's progress doc (for TheShortlist, `docs/progress.md`, screenshots in `docs/progress/<date>-<slug>.png`) with a screenshot of the channel or video page, and record any format change in `decisions.md` so the docs always describe what was actually shipped.
