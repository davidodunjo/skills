---
name: delegating-to-subagents
description: Use when about to spawn a subagent or split work across agents.
---

Delegate only when the work splits into many independent pieces, is larger than one context window, or is routine work with a long cost tail, where a strong model working alone occasionally spirals and the spiral should happen at worker rates. Work that fits in one context is a model-choice problem, not a delegation problem: try the orchestrator's own model at lower effort first, because in Anthropic's measurements that beat delegation whenever the work didn't need splitting. A single dependent chain stays with the orchestrator too, since the brief, handoff and merge cost more than they save. Delegation also gives up some accuracy (10 to 12 points on Anthropic's corpus benchmark) in exchange for roughly half the cost and a fraction of the wall-clock time, so take that trade on purpose. Keep the planning, decomposition, judgment calls and final synthesis; hand off the token-heavy execution.

Choose the model per task and set it explicitly on every spawn, since a subagent otherwise inherits the orchestrator's. Start efficiency-first and move up only for a concrete capability gap. Haiku 5.5 is the fastest and cheapest ($0.10 / $0.50 per million tokens), and Anthropic names sub-agent work as its job: locating and listing, reading and summarizing files, extraction, mechanical edits and renames, running checks and reporting results. Sonnet 5.5 ($2 / $10, twenty times Haiku) takes everyday coding: implementing a well-specified change, writing tests, reviewing a diff against stated criteria. Opus 5.5 ($4 / $20, twice Sonnet) is reserved for long-running agentic work, ambiguous design, architecture and hard debugging. Fable 5.1 ($10 / $50) only when Opus at `xhigh` or `max` still falls short, and only when David asks for it. When a task fails, escalate one tier once with a note on what failed instead of retrying at the same tier. Where effort can be set, lower it before raising the model, and re-test rather than carrying a level over, since 5.5 recalibrated it: Sonnet defaults to `high` and does well at `medium` on well-specified coding, Haiku and Opus default to `medium`. Anthropic's savings figures are directional and came from Fable orchestrators with Sonnet workers, so treat any other pairing as unmeasured.

Brief every worker with the objective, the relevant files, constraints, the deliverable, the checks to run and a stopping point, and keep parallel workers off the same files. Give every delegated agent the project's shared `agent-guide.md` and save its brief in the repo, not in session scratch space, so a dead job can be rerun by the next session. Read what comes back and run proportionate checks before reporting, never forward a worker's claim unverified.
